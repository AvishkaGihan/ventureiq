## 3. Successes & Wins

- **Defense-in-Depth Sanitization (Story 3.1):** Implemented Unicode normalization, zero-width character stripping, and pattern-based protection against prompt injection attacks before reaching LLM resources.
- **Low-Cost Plausibility Routing & Caching (Story 3.2):** Established quick plausibility evaluation (pass/refine/reject) using lightweight LLM configurations. Results are cached in Redis db1 for 7 days, reducing redundant LLM calls.
- **Cinematic & Clean Flutter UI (Story 3.3):** Designed a beautiful idea input form using VentureIQ's theme tokens, including focus glow states and a smooth, animated optional context expander.
- **Platform-Native Voice Dictation (Story 3.4):** Successfully integrated native speech-to-text APIs with SnackBar permissions handling, real-time transcription insertion, and Reduce Motion support.

---

## 4. Challenges & Technical Friction

- **Text Duplication in STT (Story 3.4):** Voice recognition partial updates initially caused exponential text duplication in the text controller. Solved by updating text cursor tracking and diff-based appending logic.
- **Overly Aggressive SQL Regex (Story 3.1):** Initial SQL injection patterns blocked normal words like "union" and "select" in business descriptions. Resolved by switching to strict word-boundary checks.
- **Validation Message Clash (Story 3.3):** Pydantic schema-level `min_length` constraints preempted custom sanitization guidance responses. Corrected by aligning UI validation behavior to let detailed guidance pass through.
- **Deceptive Hidden State (Story 3.3):** Closing the optional context expander left entered text in the form state. Patched to ensure state fields are reset on collapse.

---

## 5. Key Insights & Systemic Learnings

- **Strict Validation Separation**: Schema constraints should validate basic structural safety, while contextual business logic (like idea length guidelines) is better handled in service layers to deliver friendly, encouraging prompts.
- **Native STT Performance**: Native on-device speech recognizers are highly performant and cost-effective, but they return frequent partial updates that require careful text controller synchronization.
- **Caching High-Entropy Queries**: Caching LLM assessments requires thorough text normalization (casing, whitespace, punctuation stripping) to prevent cache misses on identical ideas.
