## 3. Successes & Wins

The team successfully delivered a secure authentication boundary:
- **Atomic Upgrade & Data Retention (Story 2.3):** Implemented a seamless Firebase account-linking flow that merges anonymous data into Google sign-in profiles atomically, preventing orphaned user data.
- **Custom Token Exchange & Rotation (Story 2.1):** Created a secure JWT exchange mechanism (`POST /auth/exchange`) with single-use refresh token rotation tracked in Redis, enhancing security.
- **Resilient Sliding Window Limiting (Story 2.4):** Designed a robust Redis-backed sliding window rate limiter that strictly enforces user-based limits (3 reports/month for free tier) and fails open/closed consistently.
- **Compensating Unlink Flow (Story 2.3):** Added defensive unlinking logic on the client to revert Firebase credentials if backend upgrade API calls fail during linking, preventing corrupt states.

---

## 4. Challenges & Technical Friction

Several systemic challenges were surfaced and successfully patched:
- **Infinite Router Loop (Story 2.2):** An infinite navigation redirect loop occurred when the router triggered anonymous sign-in upon unauthenticated state transitions. Fixed by introducing true unauthenticated states.
- **Secure Storage Concurrency (Story 2.2):** Concurrent read/write conflicts locked up key storage operations. Resolved by queueing storage transactions in `token_storage.dart`.
- **Google Sign-In Cancellation Crashing (Story 2.2 & 2.3):** Handled null dereferences when users cancelled the Google Sign-In prompt.
- **Dual-Write State Desync (Story 2.4 - Tech Debt):** Upgraded users will experience a lag in JWT claims validation until a re-auth is triggered. Enlisted as deferred technical debt for post-V1.

---

## 5. Key Insights & Systemic Learnings

- **Atomic Recovery Design**: When executing multi-step distributed operations (e.g. Firebase link + Backend upgrade), client-side compensating actions are essential to maintain system sanity on network failures.
- **Isolate Redis Routing Early**: Keeping db2 rate limits separated from db1 caches and db0 streams prevents key pollution and ensures rate-limit policies can expire cleanly without affecting caching.
- **Proactive Test Mocks Pay Off**: Creating the auth state mock helper beforehand significantly accelerated our widget test coverage and simplified verifying complex routing scenarios.
